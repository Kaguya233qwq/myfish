# 渔渔 · 商品管理插件

Vue 3 + TypeScript + Vite 前端、FastAPI Web API、SQLite 持久化任务与订单。
启用后由引擎加载插件并启动 HTTP 服务，退出时关闭服务及任务。
构建产物随插件打包，运行时不需要 Node 或前端开发服务器。
支持虚拟与实物商品档案、用户手动选类目、发布/下架及订单跟踪。
插件标识为 `fishy`，默认数据目录为 `data/plugins/fishy/`。

## 安装与启动

在项目根目录安装可选依赖：

```powershell
uv sync --extra fishy
# 或 pip install 'myfish[fishy]'
myfish run
```

源码开发环境也可以安装本目录的 `requirements.txt`。
插件默认关闭，需在 `config.toml` 中设置 `[plugins.fishy]` 的 `enabled = true`，然后重启。
默认地址为 http://127.0.0.1:8787 。没有配置适配器时后台仍可启动；
商品发布及订单交付需要已登录的闲鱼适配器。前端会显示账号连接状态。

适配器解析平台交易通知并发出 `fish.trade` 事件，插件收到后查询订单、关联会话。定时任务补充同步，快照保存在插件数据目录的 `orders/` 下。订单变更通过 `fish.order.discovered` 和 `fish.order.updated` 事件分发。

首次启动会在插件数据目录生成 `setup.token`，终端输出文件位置。
打开后台，输入文件内令牌并创建管理员账号。没有默认账号或默认密码。
初始化完成后文件被删除，初始化接口永久关闭。

`config.toml` 配置：

```toml
[plugins.fishy]
enabled = true
host = "127.0.0.1"
port = 8787
poll_seconds = 60
listing_sync_seconds = 300
listing_sync_batch = 20
session_hours = 12
secure_cookies = false
# data_dir = "data/plugins/fishy"
# public_origin = "https://goods.example.com"
```

已有闲鱼适配器时，插件会启用其订单状态跟踪。周期同步也会补偿消息漏收。
插件每次同步最多读取 10 页、每页 20 条订单，不承诺补齐所有历史订单。
默认仅监听本机；通过反向代理开放访问时配置正确的 `public_origin`，
使用 HTTPS 并设置 `secure_cookies = true`。代理必须转发正确的 Host，
插件不会无条件信任转发头。

## 商品与交付

1. 新建商品时选择虚拟商品或实物商品、闲鱼账号及商品品类。
2. 虚拟商品填写固定文本或下载链接；实物商品填写发布数量和运费。
3. 保存后自动同步至闲鱼草稿箱。上传图片后可立即或定时发布，也可关联已有商品 ID。
4. 虚拟商品的平台发布数量为 1；实物使用填写的数量。
5. 开启自动交付后，系统先回查付款、退款、买家和商品信息，再发送交付内容并确认无需物流发货。
   缺少买家会话时会尝试查询；无法匹配时停止交付。
6. 固定内容可重复交付。每个订单保存独立的发送进度，重试不会重新发送已确认发送的内容。

实物订单只同步交易状态，请在闲鱼 App 完成寄件和填写物流单号。
商品发布使用账号默认地址。

### 数据升级

启动时自动迁移数据库至 v9，保留账号、商品、订单和历史加密数据。
本版移除卡密库存功能，不再支持导入、库存分配和耗尽下架。
旧卡密商品停止自动交付，尚未执行的交付、发布和恢复上架任务取消；执行中任务标记为待核对。
需要继续使用的商品，请在“编辑交付内容”中填写固定文本或链接，再按需开启自动交付。
已发送或发送结果不明确的记录不会被覆盖；不要用旧版本插件打开升级后的数据库。

### 虚拟商品售后自动上架

固定内容虚拟商品售出后，系统保存订单交付内容并为原商品创建一次恢复上架任务。
该流程不依赖自动交付开关或买家会话。人工下架、商品编辑中或上架结果待核对时不自动恢复。
任务执行前回查售出订单，确认有效后以平台数量 1 恢复；退款或关闭的订单不恢复。
每笔订单的任务记录在 `sale_reshelves`，重复通知和重启不会重复创建任务。

当前使用原商品编辑接口；售出状态 1 仅由有售出订单关联的任务显式启用，普通恢复操作接受主动下架状态 -2。
提交后回查商品是否在售或审核中。售出状态的恢复经过模拟测试，尚未执行真实平台写入验证。

### 自动擦亮

商品列表提供“设置自动擦亮”和“立即擦亮”。新增商品时也可勾选“上架后自动擦亮”。
默认关闭，按商品开启，虚拟和实物商品均支持。间隔可设为 24–168 小时，默认 24 小时。
草稿和已下架商品不参与调度；未登录账号等待恢复连接。

接口为 `mtop.taobao.idle.item.polish` v1.0，参数 `{"itemId":"商品ID"}`。
协议线索来自[参考项目的擦亮实现](https://github.com/zhinianboke/xianyu-auto-reply/blob/main/scheduler/app/services/scheduler/polish_task.py)。
该项目 URL 版本为 1.0，查询版本写为 2.0；本实现使用 URL 和查询版本均为 1.0，
真实请求已获得 `FAIL_BIZ_ITEM_ERROR_POLISH_DUPLICATE::一天只能擦亮一次` 响应。
当前商品当天已擦亮，因此真实验证覆盖的是每日限额分支，未获得新的成功擦亮回执。

- 成功更新最近成功时间，并按设定间隔安排下一次。
- 当天已擦亮记为“已跳过”，不计入本次成功；本地从收到响应后至少等待 24 小时。
  任务说明会记录“平台确认该商品已擦亮”；冷却期间再次点击会提示已确认的状态和下次可执行时间。
  自动任务排队或执行期间点击“立即擦亮”会返回同一任务。
  24 小时是本地调度间隔，不依赖平台具体在何时重置每日额度。
- 同账号请求至少间隔 30 秒；登录/验证错误退避 1 小时，限流退避 6 小时。
- 商品状态不支持擦亮时暂停调度，保留自动擦亮开关；状态同步确认重新在售后清除暂停提示并恢复调度。
  最近成功擦亮的间隔和账号级限流继续生效。审核中、仍下架或结果待核对时不恢复。
  旧版本因状态错误关闭的开关，更新后同步商品状态可清除提示；需要继续自动擦亮时重新开启一次。
- 超时或重启时正在执行的任务标记“待核对”，不自动重发；该账号其他擦亮请求退避 1 小时。
- 关闭自动擦亮会取消尚未执行的任务；已发送的请求等待结果。下架优先取消待执行擦亮。

页面显示擦亮状态、最近成功、下次可执行时间和错误信息；任务页保留执行结果。
`tests/live_polish_check.py --product-id <本地商品ID>` 会真实擦亮指定的在售商品，
只用于显式验证，不在普通测试中运行。

### 闲鱼草稿箱同步

后台添加商品会在同一数据库事务中保存商品和草稿同步任务；后台编辑保存后也会自动排队同步。
已有平台商品 ID 的档案不创建新草稿。保存草稿不等于商品上架，点击发布才调用正式发布接口。
图片尚未上传时也可保存草稿；正式发布需要至少一张图片。

- 创建：`mtop.idle.idleitem.draft.publish` v1.0（名字含 publish，但只保存草稿）。
- 更新：`mtop.idle.idleitem.draft.edit` v1.0，携带第一次返回的 `draftId`。
- 草稿 ID 是不透明字符串，例如 `6673_1792242435499`，不能按数字商品 ID 处理。
- 页面显示等待同步、同步中、已同步、同步失败及平台草稿 ID；确认失败可点击重试同步。
- 超时、响应丢失或进程退出时保留任务错误日志。同步、编辑、上架、下架任务互斥。

本版以后台内容为准，单向推送草稿，不拉取客户端手动修改，也不删除客户端草稿。
后台再次保存会覆盖该平台草稿的对应字段。正式上架后不承诺平台自动移除草稿副本。
接口依据上方官方发布页脚本实现，操作全程在后台完成，不要求扫码进入手机编辑。
交付内容不作为草稿内容上传，只有商品介绍、图片、价格、类目、数量和配送配置参与同步。

显式真实验证脚本 `tests/live_draft_check.py` 会创建一份标记为“请勿发布”的测试草稿并更新它，
不会上架商品；可以通过 `--draft-id` 指定已有测试草稿，仅验证更新。普通单元测试不调用真实平台。

发布结果不明确时不会再次创建商品：先到闲鱼核对，
已发布的在后台关联平台 ID；管理员在任务队列查看失败任务的错误日志。
当前发布功能使用现有 PC 发布协议，平台可能限制特定虚拟商品类目；
平台未确认成功不会显示为在售。

已关联商品可通过“同步状态”回查平台状态；主动下架后可点击“恢复上架”，
使用原商品编辑链路并保留商品 ID，不创建新草稿或新商品。
虚拟商品恢复数量为 1，实物使用档案中的发布数量。
仅处理平台状态 -2，售出、审核、系统下架和多规格商品不提交恢复请求。
提交后回查原商品为在售才标记在售；返回 -9 标记审核中，超时或回查失败转为待核对任务。
状态同步直接读取已关联商品的编辑详情，不依赖可能触发安全验证的公开详情。
已关联商品按编辑详情的状态显示：0 为在售，-9 为审核中，-2 为主动下架。
卖家 ID 被隐藏不覆盖明确的商品状态；写操作仍需校验归属。
插件启动后自动轮询已关联商品，每个账号每轮最多 20 件，逐件间隔 1 秒。
每 300 秒开始下一轮；超过批量上限时按商品 ID 轮转，跳过待执行的上下架任务。
账号未连接时跳过；请求失败停止该账号本轮查询并保留原状态，不影响订单同步。
后台通过状态同步回查原商品状态。

此链路已通过模拟接口、本地集成测试，并对一件主动下架商品验证恢复上架及原 ID 保留。
普通账号的完整已下架列表接口尚未确认；“同步状态”仅覆盖已关联商品。

### 在售商品编辑

在“商品管理”选择在售商品的“编辑并发布”。表单读取远端详情，支持标题、
描述、售价、图片增删和排序、数量及实物运费；类目、账号和商品 ID 沿用原商品配置。
“保存编辑候选”仅保存后台候选；“提交编辑并发布”加入原商品编辑任务，不新建商品。
虚拟商品发布数量为 1。

提交前重新读取详情；手机端已修改商品时停止提交，需要重新读取候选。
平台回查为在售且内容与候选一致后，才更新本地档案；审核中保留原档案和候选，
自动状态同步在审核结束后继续核对内容。超时或内容不一致时进入待核对，不自动重发。
管理员在任务队列查看失败任务的错误日志。

编辑与发布、上下架及擦亮互斥。新版启动时自动迁移数据库至 v6；
执行中断的编辑任务标记为待核对。编辑提交仍需有效的账号归属信息，遇到安全验证时
保留候选，完成验证后再提交。

本次验证包括真实账号只读打开编辑详情、模拟接口写入和完整浏览器编辑流程；
没有为了测试修改真实在售商品的标题、价格或图片。

### 避免重复交付

固定内容虚拟商品可随时通过“编辑交付内容”修改文本或下载链接，无需重新编辑或发布闲鱼商品。
新内容加密保存，并同步替换尚未开始发送的预留订单快照；发送中、结果待核对及已发送订单
保留原快照，不自动补发。发送任务在领取订单时读取最新快照，避免并发修改后发送旧链接。
交付内容只在专用编辑接口返回，列表和审计日志不包含明文。

交付状态：`pending → reserved → sending → sent → completed`。

- `reserved` 已保存交付内容，尚未进入发送。
- `sending` 已进入远端发送，遇到超时/进程退出时结果可能不明确，禁止自动重发。
- `sent` 表示消息已写入 WebSocket，不等于买家已阅读；重试此阶段只确认平台发货。
- `completed` 表示平台发货接口成功，或重新查询已处于发货/完成状态。

任务队列记录失败原因、异常类型和代码位置，详细错误日志仅管理员可查看。
界面不提供已执行、未执行等人工结果确认操作。

程序重启时在执行的任务标记为待核对，不自动重新发起可能重复的发布/发送。
恢复时保留原交付进度；退款不会触发补发。

## 后台账号与数据

- 管理员：商品、任务、账号创建/停用/重置密码、审计记录。
- 运营：商品、订单和任务；不能管理团队及审计记录。
- 密码使用独立随机盐的 scrypt 散列；数据库仅存会话令牌散列。
- Cookie 为 HttpOnly、SameSite=Strict，支持 HTTPS Secure 模式。
- 写入接口要求会话 CSRF 令牌，并检查请求来源。
- 登录尝试按账号和来源限流；会话到期、退出、撤销、修改密码及停用后失效。
- 不提供公开注册；管理员最多可保留 20 个同账号有效会话。

默认数据目录 `data/plugins/fishy/`：

| 文件 | 用途 |
| --- | --- |
| `fishy.sqlite3` | 账号、订单、任务、审计及加密交付内容 |
| `encryption.key` | 交付内容的 Fernet 加密密钥 |
| `media/` | 校验并重新编码的商品 JPEG 图片 |
| `setup.token` | 仅首次初始化期间存在 |

请将数据库与原加密密钥一起备份；缺少密钥时拒绝生成新密钥来覆盖已有数据库。
商品与订单列表不返回交付内容明文，交付日志不记录正文。
后台账号与闲鱼 Cookie 分开管理。闲鱼账号仍通过终端登录，不通过后台接收 Cookie。

忘记密码：停止主程序后在本机运行（命令交互输入新密码，撤销该账号所有会话）：

```powershell
python -m myfish.builtin_plugins.fishy --data-dir data/plugins/fishy --username admin
```

## 前端开发与测试

```powershell
cd src/myfish/builtin_plugins/fishy/frontend
npm.cmd ci
npm.cmd run build
# 开发时 npm.cmd run dev；反向代理 /api 到 127.0.0.1:8787
# 浏览器测试使用本机 Edge 和临时数据库，所有闲鱼调用为模拟：
$env:NO_PROXY = '127.0.0.1,localhost'
npx.cmd playwright test
```

本地 Python 测试在 `src/myfish` 下执行 `python -m unittest discover -s tests -v`。
覆盖认证、CSRF、权限、会话撤销、固定交付、旧数据升级、交付恢复、
虚拟/实物隔离、显式类目和运费传参、旧数据库迁移、
不明确结果不重发、服务启动关闭和插件生命周期。浏览器测试覆盖初始化、
商品/订单操作、交付、团队及移动端布局。

这些业务写入验证使用模拟闲鱼接口；没有真实发布商品、下架商品或向买家发送交付内容。
平台实测需要指定测试商品及订单。

下架协议依据[闲鱼 PC 商品页脚本](https://g.alicdn.com/idle-pc/xy-site/0.0.168/js/p_item-index.js)
中的 `mtop.taobao.idle.item.downshelf` 2.0、`itemId` 请求；使用的是下架而非删除接口。
