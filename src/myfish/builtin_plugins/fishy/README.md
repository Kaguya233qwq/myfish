# Fishy 商品管理插件

Fishy（渔渔）为 Myfish 提供商品管理后台，支持商品导入、草稿同步、发布与上下架、订单跟踪、虚拟商品固定内容交付及自动擦亮。

后台账号与闲鱼账号独立管理。闲鱼账号通过 Myfish 适配器登录，后台用于管理商品、订单和任务。

## 快速开始

### 启用插件

在工作区的 `config.toml` 中添加：

```toml
[plugins.fishy]
enabled = true
host = "127.0.0.1"
port = 8787
```

同步依赖并启动：

```bash
myfish sync
myfish run
```

源码工作区使用 `uv run myfish sync` 和 `uv run myfish run`。Docker 部署会在启动时自动同步依赖，参见[项目部署说明](../../../../README.md#3-docker-部署)。

浏览器访问 <http://127.0.0.1:8787>。后台可在未配置适配器时启动；平台商品操作及订单同步需要已登录的闲鱼账号。

### 初始化管理员

首次启动时，插件在数据目录生成 `setup.token`，启动日志会显示文件位置。在初始化页面输入该令牌并创建管理员账号。

系统不提供默认账号或密码。初始化完成后，令牌文件删除，初始化入口关闭。

## 配置

以下选项均位于 `[plugins.fishy]` 下。

| 选项 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | `false` | 是否启用插件 |
| `host` | `"127.0.0.1"` | HTTP 服务监听地址 |
| `port` | `8787` | HTTP 服务端口 |
| `poll_seconds` | `60` | 订单同步间隔，单位为秒，范围为 10–3600 |
| `listing_sync_seconds` | `300` | 商品导入及关联商品状态同步间隔，单位为秒，范围为 60–86400 |
| `listing_sync_batch` | `20` | 每个账号每轮状态同步的商品数量，范围为 1–100 |
| `session_hours` | `12` | 登录会话有效期，单位为小时，范围为 1–72 |
| `secure_cookies` | `false` | 是否仅通过 HTTPS 发送会话 Cookie |
| `public_origin` | `""` | 对外访问来源，例如 `https://goods.example.com` |
| `data_dir` | 未设置 | 插件数据目录；默认使用 Myfish 数据目录下的 `plugins/fishy/` |

通过反向代理开放访问时，应配置 `public_origin`、启用 HTTPS 并设置 `secure_cookies = true`。代理需要保留正确的 Host。

## 商品管理

### 导入在售商品

闲鱼账号连接后，后台自动分页导入该账号的在售商品，也可在商品管理页点击对应账号的“同步商品”。

导入包括商品 ID、标题、售价和在售状态。新档案显示“待设置商品类型”，需要选择实物或虚拟商品；虚拟商品还需设置交付内容，才能开启自动交付。自动擦亮默认关闭。

同步按账号和商品 ID 去重，不覆盖已有档案及交付配置，也不会因平台列表缺少商品而删除本地记录。分页失败时保留已导入记录，可重新同步。商品描述、完整图片及编辑字段通过“编辑并发布”读取平台详情。

其他设备的交付内容与自动化设置不会随闲鱼登录恢复，迁移这些配置需要备份插件数据。

### 创建与发布

1. 选择商品类型、闲鱼账号和商品品类。
2. 填写商品介绍、价格及图片。虚拟商品配置固定文本或下载链接；实物商品配置数量和运费。
3. 保存商品，等待同步至闲鱼草稿箱。
4. 确认内容后立即或定时发布。也可通过平台商品 ID 关联已有商品。

草稿同步与正式发布是独立操作。发布至少需要一张图片，使用账号默认地址；虚拟商品的平台发布数量固定为 1。

草稿以后台内容为准，单向同步至闲鱼，不拉取客户端的手动修改或删除客户端草稿。交付内容不会作为商品介绍上传。

### 编辑与上下架

在售商品通过“编辑并发布”修改标题、描述、价格、图片、数量和实物运费。保存编辑候选只保存本地内容，提交后才更新平台原商品，保留商品 ID。

提交前会重新读取平台详情。商品已被其他客户端修改时，需要重新读取后编辑；审核中或结果待核对时，不会自动重复提交。

已关联商品可同步平台状态、下架或恢复上架。普通恢复操作仅适用于主动下架的商品，不处理售出、审核、系统下架或多规格商品；商品导入不提供完整的已下架商品列表。

### 自动擦亮

通过“设置自动擦亮”按商品启用，也可手动点击“立即擦亮”。虚拟和实物商品均支持，间隔为 24–168 小时，默认 24 小时。

草稿、已下架商品和未连接账号不执行擦亮。平台提示当天已擦亮时，会安排后续执行时间；状态不支持时暂停，确认恢复在售后继续调度。关闭自动擦亮会取消尚未执行的任务。

## 订单与交付

订单通过平台交易通知和定时同步更新。每轮订单同步最多读取 10 页、每页 20 条，不保证补齐全部历史订单。

### 虚拟商品

固定内容可以重复交付。开启自动交付后，系统回查订单状态、买家及商品信息，再发送内容并确认无需物流发货。无法确认付款状态或匹配买家会话时，停止交付。

“编辑交付内容”只修改本地交付文本或链接，不会修改平台商品。新内容适用于后续交付及尚未开始发送的预留订单；发送中和已发送订单保留原内容，不自动补发。

固定内容虚拟商品售出后会为原商品创建恢复上架任务。该流程独立于自动交付开关；订单退款、关闭，或商品处于人工下架、编辑和结果待核对状态时不自动恢复。

### 实物商品

实物订单仅同步交易状态，不发送虚拟内容。寄件与物流单号填写应在闲鱼 App 中完成。

### 任务异常处理

在任务队列查看执行状态，管理员可查看详细错误信息。超时、连接中断或进程退出导致结果不明确时，任务标记为待核对，不自动重发可能造成重复发布或重复交付的请求。

应先在闲鱼核实实际结果，再按任务提示处理。消息已发送不代表买家已阅读；后续发货确认失败时，不应重新发送交付内容。

## 账号与数据维护

管理员可管理团队账号、会话及审计记录；运营账号可处理商品、订单和任务。系统不提供公开注册。

默认数据目录为 `data/plugins/fishy/`：

| 路径 | 内容 |
| --- | --- |
| `fishy.sqlite3` | 后台账号、商品、订单、任务、审计及加密交付内容 |
| `encryption.key` | 交付内容加密密钥 |
| `media/` | 商品图片 |
| `orders/` | 各闲鱼账号的订单跟踪快照 |
| `setup.token` | 首次初始化令牌，初始化后删除 |

备份或迁移前停止服务，并复制完整数据目录。数据库与加密密钥必须一同保留。升级前备份数据；数据库会自动迁移，升级后不应直接使用旧版本打开。

旧版卡密库存功能已移除。原卡密商品需要改为固定交付内容，再按需开启自动交付。

忘记后台密码时，停止服务，在已安装 Myfish 的 Python 环境中执行：

```bash
python -m myfish.builtin_plugins.fishy --data-dir data/plugins/fishy --username admin
```

按提示输入新密码。重置后，该账号已有会话全部失效；使用自定义数据目录时需调整 `--data-dir`。

## 开发指南

后端使用 FastAPI 和 SQLite，前端使用 Vue 3、TypeScript 和 Vite。前端构建产物随插件打包，运行后台不需要 Node.js。

### 代码结构

| 模块 | 职责 |
| --- | --- |
| `__init__.py` | 插件生命周期、Web 服务及后台同步任务 |
| `web.py` | HTTP 路由、请求模型、权限和参数校验 |
| `service.py` | 商品、订单、交付与任务编排 |
| `catalog.py` | 平台在售商品导入 |
| `editing.py`、`polish.py`、`tracking.py` | 商品编辑、擦亮及订单跟踪 |
| `store.py`、`auth.py` | 数据存储、加密及后台认证 |
| `frontend/` | 后台页面及前端测试 |

平台 API 位于 [`myfish.adapters.fish`](../../adapters/fish/)。适配器通过 `fish.trade` 通知插件查询订单，订单变化通过 `fish.order.discovered` 和 `fish.order.updated` 事件分发。

写入 API 需要登录会话及 CSRF 令牌，部分操作仅限管理员。前端请求封装见 [`frontend/src/api/client.ts`](frontend/src/api/client.ts)。

### 前端开发

```bash
cd src/myfish/builtin_plugins/fishy/frontend
npm ci
npm run dev
```

开发服务器将 `/api` 请求代理至 `http://127.0.0.1:8787`。修改前端后执行 `npm run build`，生成供后端提供服务及打包使用的 `dist/`。目录说明见[前端文档](frontend/README.md)。

### 测试

使用 `myfish sync` 创建的 Python 运行环境，在源码目录执行：

```bash
cd src/myfish
python -m unittest discover -s tests -v
```

前端目录执行 `npm run test:e2e`。当前 Playwright 配置使用 Microsoft Edge 和 Windows `.venv/Scripts/python.exe`；其他环境需调整 [`playwright.config.ts`](frontend/playwright.config.ts) 中的浏览器与解释器路径，并先构建前端。

常规测试使用模拟平台接口和临时数据。`tests/live_*` 脚本会访问真实账号，部分脚本会创建草稿或执行擦亮，不属于常规测试流程。
